# Reproducing the Paper Experiments

This repository is the reproduction companion for *When Memory Is Not Enough:
What Drives Robustness in AI Decision Systems? Evidence from Sequential
Financial Decision-Making*. It builds on the earlier conference paper
[*MultiHedge: Adaptive Coordination via Retrieval-Augmented Control*](https://link.springer.com/chapter/10.1007/978-3-032-29924-6_39)
(ICCS 2026). Its [original conference-version repository](https://github.com/latent-systems-lab/MultiHedge)
is preserved separately; use the present repository and the protocol below for
the current robustness study.

The manuscript source is maintained in Overleaf; this repository contains its
public code and experiment companion.

## Environment

Use Python 3.10 or newer.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

`requirements.txt` records the supported dependency constraints. The original
historical environment was not preserved as a complete `pip freeze`, so these
constraints should not be interpreted as a bit-for-bit lockfile. For every new
reproduction run, record the resolved environment alongside the outputs:

```bash
python3 -m pip freeze > results/environment-freeze.txt
python3 --version > results/python-version.txt
```

Fill in the LLM provider credentials in `.env`. The simulator reads
`LLM_PROVIDER`, `LLM_MODEL`, `OPENAI_API_KEY`, and `GEMINI_API_KEY` at runtime.

## Data

The main historical experiments require local market data under `data/`:

- `AAPL.csv`, `NVDA.csv`, and `TSLA.csv` with daily OHLCV columns.
- `aapl_options.db`, `nvda_options.db`, and `tsla_options.db` SQLite option
  chains with an `options` table.
- `earnings.csv`, `cpi.csv`, `vix.csv`, and `fear-greed-2011-2023.csv` for
  macro and auxiliary signals.

The research runs used Yahoo Finance daily OHLCV data for AAPL, TSLA, NVDA, and
SPY. The 2022 broad-market robustness check uses the SPDR S&P 500 ETF Trust
(SPY), not the S&P 500 index itself. Historical option chains were obtained from
OptionsDX under commercial provider terms. The raw third-party files cannot be
redistributed by the authors and are not tracked in git; equivalent data must
be obtained directly from the respective providers. For development-only smoke
runs, synthetic sample data can be generated with:

```bash
python3 scripts/generate_sample_data.py
```

Synthetic data is useful for checking that the pipeline runs, but it will not
reproduce the paper tables.

The controlled three-regime environment used in the paper is generated by
`src/core/data_provider.py` and run through
`experiments/run_synthetic_3_regime.py`. Its default random seed is 42, and the
generated equity and Black--Scholes option data can be exported by the runner.

## Main Simulator

Run the full controller on the main evaluation horizon:

```bash
python3 main.py \
  --start-date 2021-01-01 \
  --end-date 2023-12-31 \
  --assets AAPL TSLA NVDA \
  --hedging-strategies collar straddle delta-neutral \
  --controller-mode full_llm \
  --use-llm \
  --use-memory-rl True \
  --output-dir results/main_full_llm
```

Outputs include `performance.csv`, `summary.json`, `final_portfolio.json`,
plots when enabled, and `llm_usage.jsonl`.

The main entry point fixes the NumPy and Python random seeds at 42. For the
full-system repetitions, the market inputs, prompt templates, control settings,
and decoding temperature (`T=0.0`) are held fixed. Hosted model inference is not
guaranteed to be bitwise deterministic: the repeated calls produced different
structured outputs, which then propagated through later sequential decisions.
The reported full-system dispersion therefore does not represent deliberately
changed data splits or execution seeds.

## Memory Isolation Ablation

The memory-controller ablation evaluates the paper modes directly. By default it
runs `full_llm`, `retrieval_only`, `random_retrieval`, and `no_memory`, building
a shared pre-evaluation memory buffer first.

```bash
python3 experiments/run_memory_controller_ablations.py \
  --output-dir results/memory_controller_ablations \
  --random-runs 3
```

For a quick partial run, pass explicit modes:

```bash
python3 experiments/run_memory_controller_ablations.py \
  --modes retrieval_only random_retrieval \
  --random-runs 1
```

The runner writes per-mode outputs plus `summary.csv` and `metadata.json`.
Random-retrieval repetitions use seeds 42, 43, and 44 by default; deterministic
memory-isolation modes use seed 42. The runner records these values and the LLM
temperature in `metadata.json`.

## Strategy and Model Ablations

The multi-model study runner exposes named groups, so the source file does not
need to be edited between runs:

```bash
python3 experiments/run_multi_model_studies.py --group individual
python3 experiments/run_multi_model_studies.py --group pairs
python3 experiments/run_multi_model_studies.py --group providers
python3 experiments/run_multi_model_studies.py --group gpt-sweep
```

The `gpt-sweep` name is retained for command-line compatibility; it runs the
paper's coordinator-choice variants (GPT-5 Nano, Gemini-2.5-Flash Lite, and
GPT-4o Mini) and the GPT-5 stochastic-decoding variant at `T=0.7`.

To run the main strategy/model ablation batch:

```bash
python3 experiments/run_multi_model_studies.py --group paper-ablation
```

These runs require valid LLM credentials and the real market data described
above.

The paper compares coordinator choices rather than claiming a controlled model-
capacity scale: endpoints from different providers may differ in architecture,
training data, serving stack, and cost as well as nominal size.

## Robustness Checks

Auxiliary checks are packaged separately:

```bash
python3 experiments/run_spy_1y_sanity.py
python3 experiments/run_synthetic_3_regime.py
python3 experiments/run_scrambled_timeline_placebo.py
```

Short smoke checks for these scripts can be run with:

```bash
python3 experiments/run_experiment_smoke_checks.py
```

## Bootstrap Evidence

After result files are present under `results/`, run:

```bash
python3 scripts/paired_block_bootstrap_evidence.py \
  --results-dir results \
  --output-csv bootstrap_results.csv \
  --n-bootstrap 10000 \
  --block-size 20
```

The script prints the aligned strategy metrics, bootstrap confidence intervals,
one-sided p-values, and a compact robustness summary.

## Notes on Exact Paper Tables

Several paper tables were computed from repeated historical result files. If the
raw result folders are absent, `scripts/recover_paper_benchmark_table.py` can
recover selected benchmark table inputs from the historical git commit recorded
inside that script. This is useful for auditing the current draft numbers, but a
fresh public artifact should include either the raw result files or a release
archive containing them.
